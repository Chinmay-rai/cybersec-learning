# Day 33 – Splunk Log Ingestion and DVWA Traffic Analysis

## What I Did

- Verified communication between Splunk Enterprise and the Splunk Universal Forwarder running on Kali Linux
- Investigated available log sources being forwarded to Splunk
- Identified that authentication events were stored in the systemd journal rather than a traditional auth.log file
- Explored Linux logging and troubleshooting techniques using journalctl
- Configured the Universal Forwarder to monitor Apache web server logs
- Connected DVWA web traffic to Splunk through Apache access logs

## Log Sources Investigated

- boot.log
- apt history logs
- Apache access logs
- Apache error logs
- systemd journal events
- sudo and PAM authentication events

## Splunk Activities

- Used SPL searches to identify available sources and sourcetypes
- Examined forwarded log data from the Kali VM
- Verified successful ingestion of Apache access logs
- Analyzed web requests generated while interacting with DVWA

## What I Understood

- Different Linux distributions may store security-related events differently
- Splunk Universal Forwarder only sends data from configured sources
- Apache access logs provide detailed visibility into web application activity
- Real-world investigations often begin by identifying where relevant logs are stored
- Splunk can be used to monitor and analyze activity generated by web applications
